## v0.2.0 — 2026-11-05

공개 조회·콘텐츠 생성·원본 저장을 최적화하고, GitHub 관리 기능과 macOS 클라이언트의 누적 변경을 포함한다.
[최적화와 실측 기록](https://github.com/gyungsubLee/subdev-blog/blob/codex/block-editor-storage/docs/releases/v0.2.0-performance.md)에 측정 조건, 표본, 원시 근거와 남은 제한을 모았다.

각 행은 해당 단계의 관측이다. 서로 다른 커밋·네트워크 조건의 감소율을 전체 개선율로 합치지 않는다.
원본 저장 확인과 공개 완료는 다르다. 공개 workflow의 요청과 소요 시간은 별도로 남긴다.

### 포함한 변경

- 공개 목록과 본문 JSON을 미리 생성한다. 변경한 본문만 갱신하고 기존 blob을 재사용한다.
- 불변 Git 객체와 검증한 Markdown, 인코딩한 목록 응답을 재사용한다. gzip과 캐시 한도를 유지한다.
- IndexedDB에 저장한 내용을 먼저 반영한다. 즉시 백그라운드 전송하고 여러 창의 중복 전송을 막는다.
- 준비된 저장은 `createCommitOnBranch` mutation 한 번으로 반영한다. 기준 커밋과 확인 파일로 충돌과 복구를 검사한다.
- 큰 요청은 기존 Git-data 경로를 사용한다. 재시도는 같은 요청 ID와 payload를 유지한다.
- GitHub 인증으로 원본과 카테고리를 관리한다. 세션 로컬 확인, 로그인 복구와 네이티브 ACK를 보완한다.
- 승인한 Mono Press 화면, 테마 설정, 공유 버튼과 헤더 동작, 기록·분류 화면을 포함한다.
- Markdown 전용 편집 화면을 블록 편집기로 통합한다. 삭제는 즉시 반영하고 실패하면 목록을 복원한다.
- 삭제한 글을 참조하는 기존 링크와 메타데이터를 보존한다. 참조 존재만으로 삭제를 막지 않는다.
- 앱 구조와 원본·공개 자산을 분리한다. 중복 검사와 반복 fixture 준비를 줄인다.

### 호환성과 검증 한계

- 버전 기준은 `package.json`이며 lockfile과 `v0.2.0` 태그를 맞춘다. 네이티브 표시 버전도 이 값을 읽는다.
- 공개 `generation.json`은 압축 envelope v2를 사용한다. 기존 v1을 읽으며 이전 generator의 전체 생성 fallback을 확인했다.
- 실제 GitHub 최초 본문 탐색은 0.211→0.492초로 늘었다. 카테고리 직접 반복 조회도 319.22→382.90ms로 늘었다.
- 즉시 전송 측정 화면은 151.2→249.6ms로 늘었다. 원인은 미확인이며 전체 편집기 성능 동등성을 주장하지 않는다.
- Node 43.2MiB 큐 모델은 최대 RSS 약 1.31GiB였다. 실제 브라우저 대용량 안전과 24시간 방치는 미검증이다.
- 실제 쓰기·공개 workflow 성공과 원본 SHA 보존을 확인한 과거 실측을 첨부한다. 과거 실패 로그도 유지한다.
- 이번 후보의 검사·빌드·정확한 커밋·Actions 실행·산출물·체크섬은 [빌드 이력](https://github.com/gyungsubLee/subdev-blog/blob/codex/block-editor-storage/BUILD_HISTORY.md)에 기록한다.

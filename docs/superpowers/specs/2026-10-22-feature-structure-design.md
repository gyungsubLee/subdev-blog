# 기능별 구조 리팩터링 설계

사용자가 선택한 3안으로 구조를 바꾼다. 기존 화면과 동작을 유지한다.
검색·분류·페이지 개수는 사용자의 추가 요청에 따라 독립 기능으로 나눈다.

## 책임과 의존 방향

- `app`: 앱 상태, hash 구독, 데이터 요청, 목록·상세·작성 전환을 소유한다.
- `pages`: 목록·상세·작성 화면을 조립한다.
- `features/post-search`: 검색 입력, 검색어 상태와 검색 조건을 소유한다.
- `features/post-category`: 분류 선택, 분류 상태와 분류 조건을 소유한다.
- `features/post-pagination`: 표시 개수 상태, 개수 표시와 더 보기를 소유한다.
- `features/post-list`: 대표 글 선택과 글 카드 목록을 소유한다.
- `features/post-reader`: 안전한 Markdown 렌더링, 내부 링크와 본문 이동을 소유한다.
- `features/page-explorer`: 페이지 계층 탐색을 소유한다.
- `features/post-editor`: 편집기 설정, 작성 상태, 저장·가져오기·내보내기를 소유한다.
- `components`: 레이아웃, 대화상자, 표지 그림과 아이콘을 소유한다.
- `shared`: 글 타입, 초안 저장, 문서 형식과 브라우저 다운로드를 소유한다.
- `config/site.ts`: 사이트 이름, 작성자와 소개 문구를 소유한다.
- `styles`: 공통 CSS 변수와 기본 규칙만 소유한다.

페이지는 기능과 공통 컴포넌트를 조립한다. 기능은 다른 기능의 상태를 직접 변경하지 않는다.
`BlogView`가 검색·분류·표시 개수 기능을 조합한다. 상태는 상세 화면을 열어도 유지한다.
일반 CSS를 소유 코드 옆에 둔다. 기존 클래스와 반응형 규칙을 보존한다.

## 보존할 계약

- 주소는 `#/`와 `#/post/:id`를 유지한다. 작성은 앱 상태로 전환한다.
- 검색은 제목·요약·Markdown을 대상으로 대소문자를 구분하지 않는다.
- 검색 입력·분류 선택은 표시 개수를 12로 초기화한다. 더 보기는 12개씩 늘린다.
- Escape와 빈 결과의 필터 초기화는 기존처럼 검색·분류만 지우고 표시 개수를 유지한다.
- 목록·상세 전환은 검색·분류·표시 개수를 유지한다. 작성 화면 전환은 기존 초기화 동작을 유지한다.
- 대표 글은 초안이 아니며 제목을 제외한 본문이 300자를 넘는 첫 글이다. 조건에 맞는 글이 없으면 기존처럼 첫 글을 사용한다. 보조 글은 2개다.
- 요약을 먼저 받고 선택한 글의 전체 본문을 따로 받는다. 로딩 중 본문·다운로드·편집 차단을 유지한다.
- HTML 검사, 이미지 URL 제한, 내부 페이지 링크와 제목·블록 이동을 보존한다.
- 페이지 계층은 펼친 가지의 자식만 렌더링한다.
- 편집기와 Shiki는 작성 화면을 열 때 불러온다. 선택한 글이 바뀌면 편집기 상태를 새로 만든다.
- 자동 저장은 650ms다. 이미지 업로드는 5MiB, 문서 가져오기는 10MiB로 제한한다.
- 초안 저장 키 `second-brain:drafts:v1`과 문서 형식을 유지한다. 손상된 초안을 덮어쓰지 않는다.
- 파서와 문서 생성 코드는 Node CLI에서도 사용할 수 있다.
- 새 의존성을 추가하지 않는다. 게시·인증·동기화 기능을 추가하지 않는다.

## 설정과 CSS

사이트 문구는 `config/site.ts`에 둔다. 기능별 수치는 소유 기능의 설정에 둔다.
SVG 좌표와 문서 검증 규칙은 사용하는 모듈에 유지한다.
앱 로딩·오류 CSS는 편집기와 분리해 즉시 불러온다.
Markdown·BlockNote가 생성하는 클래스와 기존 미디어 조건을 보존한다.

## 검증

변경 전 `npm run check` 결과는 64개 통과, 실패 0개다.
기존 DOM·저장·문서·편집기 검사를 새 경로로 연결한다.
검색·분류·더 보기의 조합과 상세 왕복 상태 보존 검사를 추가한다.
전체 검사, 수집·자산 검사와 프로덕션 빌드를 실행한다.
Chrome 연결이 제공되면 실제 화면·입력을 검사한다. 연결 실패는 DOM 검사와 구분해 보고한다.

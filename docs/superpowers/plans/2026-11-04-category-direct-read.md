# 카테고리 직접 조회 실행 계획

Goal: 카테고리 조회의 별도 HEAD 확인을 제거하고 실제 데이터를 한 번에 읽는다. 저장 충돌 검사는 유지한다.
Scope: 기존 서버 조회 경로, 필수 GitHub 읽기 재시도, fixture와 회귀 검사, 실측과 업무 기록. UI·공개 조회·저장 계약은 유지한다.

- [x] 데이터 조회1회, HEAD0회인 실패 검사를 작성하고 실행한다.
- [x] GitHub의 단일 읽기 query로 categories.json과 기준 커밋을 함께 받는다. 파일 모드·크기 검사는 유지한다.
- [x] 기존 POST 저장의 최신 HEAD·baseRevision·force:false와 재시도 식별을 보존한다.
- [x] 실제 원본 조회 전후를 같은 인증·콘텐츠·캐시 조건으로 비교한다. 실제 콘텐츠 저장·삭제는 하지 않는다.
- [x] 관련·전체 검사와 빌드, 실제 앱 조회를 확인하고 결과와 제한을 기록한다.

사용자 요청의 수정·실측 승인을 적용한다. 새 인프라나 의존성은 추가하지 않는다. 조회 결과의 contentCommit은 같은 응답의 저장 기준값이며, 별도 HEAD API 호출이나 비교는 없다.

검증 결과: `docs/research/2026-11-04-category-direct-read/README.md`. 기능 구현과 실측은 완료했다. 반복 조회 중앙값+63.68ms의 성능 차이는 사용자 수용 여부 대기다.

# GitHub 인증 복구 구현 계획

**Goal:** 승인한 1–3번을 수정하고 실제 로그인을 확인한다.
**Architecture:** 기존 OAuth·쿠키·PKCE와 권한 검사를 유지한다. 읽기 재시도, 세션 확인 중복 방지, 네이티브 수신 확인만 보완한다.
**Tech Stack:** Node fetch, React, Swift URLSession/WKWebView. 새 의존성 없음.
**Spec:** 사용자 승인과 `docs/research/2026-11-04-github-auth/README.md`.

## 제약

UI·문구·세션 최대 3600초·권한·CSRF·불변 파일 캐시는 유지한다. 기존 dirty 파일은 보존한다. 현재 checkout에서 직접 구현한다. 커밋과 배포는 하지 않는다.

## 작업

- [x] 서버: 통신 실패의 GET만 최대 3회 시도한다. OAuth 코드 교환은 15초 제한과 무재시도를 적용한다. 진행 중 OAuth state/verifier를 재사용한다. 실패 콜백은 정상 세션을 삭제하지 않으며 다른 pending 쿠키도 보존한다.
- [x] 웹: 세션 확인은 30초 제한, 동시 요청 병합, 일시 실패 1회 재시도를 적용한다. 온라인·창 복귀 시 5초 간격 제한으로 확인한다. 로그아웃 뒤 이전 응답은 무시한다.
- [x] 네이티브: 활성 로그인 시작을 합친다. 완료 결과는 수신 확인 POST 전까지 보존하며 원래 10분 만료를 유지한다. Swift는 조회 통신·5xx 실패를 최대 3회 시도하고 쿠키 전달 뒤 수신을 확인한다.
- [x] 각 경계의 회귀 검사를 먼저 실행해 실패를 확인한다. 수정 뒤 관련 검사·타입 검사·전체 검사와 빌드를 실행한다.
- [x] 실제 Chrome 로그인과 새 네이티브 빌드의 로그인 왕복을 확인한다. 같은 계측기로 GitHub 시간·요청 횟수를 비교한다.

## 검토할 실패 조건

오래된 콜백, 권한 거부, 로그아웃과 확인 응답의 경합, 완료 응답 유실, 만료한 네이티브 flow를 검사한다. 오래된 진단 파일은 수정 전 증거로 보존하며 수정 후 검증 대상으로 쓰지 않는다.

# GitHub 세션 인가 실행 계획

사용자가 승인한 정본은 `.project-context/tasks/github-session-hour.md`다. 같은 checkout에서 이 채팅이 구현과 검사 실행을 소유한다.

- [x] 인증 호출 경로와 실제 앱·서버를 확인한다. 실패 검사로 로그인 인가 누락을 재현한다.
- [x] 최초 콜백에서 사용자·설치·두 저장소·구성을 검사한다. AES-GCM 세션에 사용자·발급 시각·설정 결속값을 넣는다.
- [x] 이후 세션은 로컬 검증한다. 콘텐츠 HEAD는 세션에 넣지 않는다. Origin·CSRF·충돌 검사를 유지한다.
- [x] 구형·만료·변조·설정 변경과 콘텐츠 접근 거부를 검사한다. fixture는 새 인가 계약을 사용한다.
- [x] 명시적 네이티브 재시작은 보호된 시작 요청으로 구분한다. 중복 시작과 ACK 동작은 유지한다.
- [x] 기존 전체 검사와 네이티브 검사, 빌드를 실행한다.
- [x] 실제 앱에서 OAuth·callback·쿠키 전달·앱 복귀·보호된 조회를 확인한다. 같은 입력으로 이전 경로와 요청 횟수·시간을 비교한다.
- [x] 변경 범위와 검사 결과, 미확인을 증거와 업무 기록에 남긴다.

범위 결정: 이미 승인한 인계 설계를 실행한다. 추가 설계 승인이나 새 worktree는 필요하지 않다. 공개 콘텐츠·카테고리 글쓰기·UI 변경은 보존한다. 커밋·푸시·배포·실제 콘텐츠 저장과 삭제는 하지 않는다.

검토 초점은 짧은 토큰 수명, 느린 최초 인가, 구형 쿠키, 최신 콘텐츠 HEAD, 늦은 네이티브 callback이다. 자동 검사의 시간 전진은 실제1시간 방치와 구분한다.

최종 검토에서 네이티브 재시작의 OAuth 쿠키 재사용을 실패 검사로 확인했다. 새 네이티브 flow는 이전 challenge 쿠키만 제외해서 새 state를 발급한다. 일반 웹 중복 로그인 동작은 유지한다.

최종 검사와 실측의 제한은 `docs/research/2026-11-04-github-auth/session-hour/README.md`에 기록했다. 전체 검사2개 기능 실패를 해결했다고 주장하지 않는다.

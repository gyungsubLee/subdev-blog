# 캐시 우선 표시와 백그라운드 저장

사용자는 첫 화면을 저장한 내용으로 표시하고, 저장·게시 버튼을 누르면 클라이언트에 먼저 반영한 뒤 백그라운드로 동기화하도록 승인했다. 입력할 때마다 자동 게시하지 않는다.

같은 checkout의 기존 수정과 UI를 보존한다. 공개 콘텐츠 생성·GitHub 원격 게시의 다른 작업은 변경하지 않는다. 새 의존성이나 다중 사용자 병합 기능은 추가하지 않는다.

- [x] 카테고리 서버 캐시를 완성한다. 반복·동시 조회는 GitHub0회다. 명시적 새로 읽기와 저장 시 캐시를 무효화한다. 실패·진행 중 무효화·범위 분리를 검사한다.
- [x] 공개 목록·이미 읽은 본문은 브라우저 캐시에서 먼저 연다. 카테고리 화면도 기기 저장소의 마지막 원본과 편집 내용을 먼저 표시한다. 네트워크 오류로 캐시를 지우지 않는다.
- [x] 저장·게시 요청은 정확한 payload를 기기에 보관하고 순서대로 전송한다. 화면을 이동해도 응답을 기록한다. 새로 열거나 온라인으로 돌아오면 보관한 요청을 재개한다. 인증 정보는 저장하지 않는다.
- [x] 저장 요청의 로컬 변경을 표시한다. 실패하면 로컬 변경과 같은 요청 ID를 유지한다.401/403/409는 자동 반복하지 않는다. 기존 오류·게시 상태 UI를 사용한다.
- [x] 저장 충돌·삭제 확인·초안 공개 경계·Origin·CSRF를 유지한다. 실제 사용자 콘텐츠를 저장하거나 삭제하지 않고 fixture에서 검증한다.
- [x] 관련 검사·전체 검사·빌드와 실제 브라우저 캐시 표시를 확인하고 반복 조회를 다시 실측한다.

범위 결정: 서버 캐시만으로 첫 화면을 기다리지 않게 할 수 없으므로 클라이언트 읽기와 저장 요청의 수명을 함께 수정한다. 로컬 반영은 원격 완료로 표시하지 않는다. 첫 접속의 빈 캐시에서는 최초 데이터 조회가 필요하다. 서버 캐시는 프로세스 수명 동안 유지하며 외부 변경은 명시적 새로 읽기 또는 저장 충돌 뒤에 반영한다.


## 확정 정책과 실행

정본은 `docs/superpowers/specs/2026-11-04-local-first-sync.md`다. 사용자가 정책 그대로 구현과 E2E·실측을 명시했다. inline 구현과 독립 읽기 검토로 진행하며 재승인·커밋·원격 반영은 하지 않는다.

추가 대상: 서버 `content.mjs`의 operations 배열과 단일 커밋, 클라이언트 `sync-core.mjs`·`sync-store.mjs`·`background-sync.mjs`·`sync-cleanup.worker.mjs`, 기존 저장 호출부와 읽기 훅이다. 검토 초점은 응답 유실, 중복 탭, 전송 중 추가 수정, 정리와 저장의 경합, 용량 한도다.

- [x] 두 글의 단일 커밋과 동일 묶음 재시도 검사를 실패에서 통과로 만들었다.
- [x]5초 합치기·중복 소유자·응답 유실 복구·확인한 기록만 일일 정리 검사를 실행했다.
- [x] 실제 IndexedDB·Worker와 UI를 연결한 E2E, 기존 회귀 검사, 실제 앱 읽기와 실측을 완료한다.

검증 결과: 전체 554/556(기존 편집기 실패 2개), 최종 관련 기능 46개·복구/한도 11개·HTTP E2E 1개 통과. 실제 GitHub 카테고리 중앙값 432.03→0.37ms, 외부 1→0회. Chrome 반복 화면 508.4→102.8ms. 벌크 3작업은 3→1요청·커밋이다. [상세 결과](../../research/2026-11-04-local-first-sync/README.md)에 미확인 항목과 실패 기록을 분리했다.

재검증: 완료 알림과 정리의 확인 조건 두 곳을 보완했다. 전체574/576·관련13개·Chrome/HTTP E2E·빌드를 확인했다. 대용량 메모리 안전은 보류하며 [새 판정](../../research/2026-11-04-local-first-sync/reverification-2026-11-04/README.md)을 따른다.

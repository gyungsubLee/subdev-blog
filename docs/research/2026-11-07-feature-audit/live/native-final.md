# 네이티브 앱 최종 직접 검사

최신 웹 빌드를 실제 앱에서 다시 읽고, 로그인·목록·검색·로그아웃·종료를 확인했다.
루트 담당자가 이 검사를 단독 실행했다. 캐시와 WebKit 저장소를 지우지 않았다.

## 실행 결과

- 정확한 앱 경로는 `.tmp/live-feature-audit/Second Brain Audit.app`이다. 검사 포트는 `55173`이다.
- 앱 도구 모음의 새로고침을 눌렀다. 만료한 세션은 기존 권한의 GitHub OAuth로 다시 로그인했다.
- 브라우저 인증 완료 뒤 네이티브 관리 메뉴와 로그아웃 버튼이 나타났다.
- 콘텐츠 관리에서 전체 3,032개, 공개 3,032개, 초안 0개를 확인했다.
- `20261107-native-crud` 검색 결과는 0개였다. 삭제한 테스트 글은 다시 나타나지 않았다.
- 마지막 복구 버튼 수정 뒤 생성한 `index-Co9rylJr.js` 빌드에서도 도구 모음 새로고침으로 같은 결과를 확인했다.
- 로그아웃 뒤 로그인 링크와 `로그인이 필요합니다`를 확인했다.
- 앱 메뉴의 `Second Brain 끝내기`로 종료했다. 실행 세션의 종료 코드는 0이었다.
- 소유 앱 PID `39196`과 서버 PID `39362`가 모두 종료됐다. `55173` 수신 포트도 없었다.
- Chrome의 전용 검사 탭과 네이티브 인증 완료 탭을 정리했다. 해당 원점의 남은 탭은 0개였다.

## 도구와 실행 환경의 경계

하위 세션의 `cua.getApp`은 지정한 30초를 넘겨 대기했다. 루트가 중단한 호출은 도구에서 `aborted by user`로 반환했다.
실제 중단 행위자는 루트였다. 사용자의 거절로 기록하지 않는다.
루트 세션에서는 같은 정확한 앱 경로에 0.63초 만에 연결했고 실제 검사를 완료했다.
이 차이의 도구 내부 원인은 미확인이다.

Chrome 확인창을 처리하는 탭 API에도 연결 시간 초과가 있었다.
루트는 Chrome의 프로필·원점·카테고리 탭을 확인한 뒤 macOS 확인창의 기존 확인 버튼을 눌렀다.
그 뒤 원본 v2와 저장 완료 상태가 나타났다. [GUI 기록](gui-results.md)은 이후 카테고리 CRUD를 별도로 기록한다.

원본 앱의 `5173` 포트 충돌은 유지된 환경 조건이다. 다른 프로젝트를 종료하지 않았다.
전용 앱 복사본은 같은 네이티브 실행 코드와 기존 UI를 사용했다. 이 결과를 원본 포트에서의 시작 성공으로 확대하지 않는다.

[바이너리 비교](native-binary-comparison.json)에서 서명 전 구간 239,568바이트의 SHA-256이 같았다.
다시 서명한 앱은 마지막 내장 서명 752바이트만 다르다. 두 파일 전체의 SHA가 같다고 주장하지 않는다.

# 서버 기능 조사 결과

2026-11-07 서버 구현과 기존 검사 233개를 조사했다. 서버 코드와 서버 검사 코드는 수정하지 않았다.

초기 검사에서 232개가 통과했다. Vite 실행 검사 1개는 샌드박스의 로컬 포트 제한으로 실패했다. root가 이후 실행한 전체 Node 검사 630개는 모두 통과했다.

## 조사 범위

- 구현: `app/server/src/handler.mjs`, `auth.mjs`, `github.mjs`, `content.mjs`, `management-read-cache.mjs`, `public-content.mjs`, `native-auth.mjs`.
- 근거: `tests/server/*.test.mjs`의 API, 인증, Git 저장, 공개 데이터, 캐시, 발행, 런타임 검사.
- 보존: 기존 `public-files.mjs` 수정과 `content` 변경을 유지했다. UI와 제품 문구를 바꾸지 않았다.

## 구현 기능과 CRUD 검사

| 기능 | 구현 동작 | 확인한 검사 |
|---|---|---|
| API 라우팅 | 직접 경로와 `/api?path=...` 경로를 지원한다. 허용하지 않은 메서드는 거부한다. | 알 수 없는 경로, 메서드 제한, 공개 API의 인증 분리 |
| GitHub 로그인 | PKCE와 state를 사용한다. 토큰은 암호화한 HttpOnly 쿠키에 보관한다. | state 변조, 취소, 다른 사용자, 만료, 이전 callback, 교체한 설정 |
| 인증과 쓰기 권한 | 소유자와 세션을 확인한다. 변경 요청은 origin과 CSRF 토큰을 함께 확인한다. | 비인증 요청, 잘못된 origin, 잘못된 CSRF, 과도한 설치 권한, 저장소 선택 |
| 문서 생성 | 새 UUID와 초기 원문을 제공한다. Markdown, editor JSON, 첨부파일을 한 커밋으로 저장한다. | 새 문서 ID, 부모와 참조 검사, editor 쌍, 첨부파일 보존 |
| 문서 조회 | 원문 Markdown과 별도 revision을 반환한다. 손상된 editor 원문은 복구용으로 반환한다. | 정확한 원문과 revision, editor 복구, 안전하지 않은 트리 거부 |
| 문서 수정 | 제목, 본문, 태그, 카테고리를 저장한다. 숨은 메타데이터와 기존 첨부파일을 유지한다. | 제목 변경, 본문 변경, 태그 저장, editor revision 충돌, 변경 없는 저장 |
| 문서 삭제 | 대상 문서의 Markdown, editor JSON, 첨부파일을 제거한다. 살아 있는 문서의 관계와 링크는 유지한다. | 삭제 범위, 남은 자식, 외부 문서 관계 보존 |
| 카테고리 생성과 수정 | `categories.save`로 이름, `parent_id`, 순서를 저장한다. 원래 sources와 숨은 필드를 유지한다. | 카테고리 CRUD, 부모 관계, 새 카테고리와 문서의 일괄 저장 |
| 카테고리 삭제 | `category.delete`는 배정 문서를 미분류로 이동하거나 함께 삭제한다. 자식 카테고리가 있으면 거부한다. | move와 delete, 상속 문서와 첨부파일, 미분류 보호, 부모 보호, 무관한 문서 보존 |
| 첨부파일 업로드 | base64 또는 청크를 검증하고 Git blob을 만든다. 크기와 SHA를 확인한다. | 잘못된 base64, 청크 결합, 5 MiB 제한, 경로 이탈, 이름 충돌, 예약 파일명 |
| 저장과 충돌 복구 | 기준 커밋과 revision을 확인한다. 요청 ID와 영수증으로 중복 저장을 막는다. | 오래된 revision, 동시 저장, 응답 유실, 재시도, 변조한 영수증, 분기 충돌 |

| 캐시와 전송 제한 | 불변 Git 객체와 카테고리 요청을 재사용한다. HEAD와 권한은 캐시에 고정하지 않는다. | 요청 합치기, 캐시 범위와 용량, 변경 뒤 무효화, 압축, 파일과 응답 크기 제한 |

카테고리 삭제 뒤 다음 화면 저장까지 이어지는 HTTP 사용자 흐름은 기존 서버 단위 검사만으로 확인할 수 없다. 해당 흐름의 UI 결함과 회귀 검사는 웹 담당자가 맡았다.

## 실행한 검사

초기 명령은 다음과 같다.

```sh
node --test --test-concurrency=2 tests/server/*.test.mjs
```

- Python subprocess가 전체 프로세스에 120초 제한을 적용했다. stdout과 stderr는 `/tmp/subdev-server-audit-initial.log`에 저장했다.
- 51.34초 뒤 실행이 끝났다. 결과는 233개 중 232개 통과, 1개 실패였다.
- 실패한 검사는 `tests/server/management-runtime.test.mjs`의 `Vite serves management requests with their method, body and separate cookies`다.
- 실패 원인은 `listen EPERM: operation not permitted 127.0.0.1:5173`이었다. 기능 assertion에 도달하기 전에 로컬 포트 열기가 막혔다.
- 초기 프로세스의 종료를 확인했다. 권한을 바꾼 개별 재실행 요청은 사용자 중단으로 결과를 얻지 못했다.

root가 이후 전체 Node 검사를 맡았다. root 보고에 따르면 630개가 135.73초에 모두 통과했으며 Vite 런타임 검사도 통과했다. 로그는 `/private/tmp/subdev-audit-full-node.log`다. 이 결과는 root가 제공한 통합 근거이며 서버 담당자가 중복 실행하지 않았다.

root가 별도로 실행한 HTTP 검사 6개도 모두 통과했다고 보고했다. 이 검사는 문서 생성·조회·수정·삭제, 카테고리 추가, 인증과 CSRF, 원자 저장 재시도, 공개 발행 흐름을 다뤘다.

## 수정과 한계

- 서버에서 새 기능 오류를 재현하지 못했다. 서버 구현과 서버 검사 코드를 수정하지 않았다.
- GitHub HTTP 의존성은 격리한 fixture로 검사했다. 발행 검사는 임시 Git 저장소를 사용했다.
- 실제 원격 저장소 변경, 실제 OAuth 로그인, 운영 토큰, 운영 배포는 검사하지 않았다. 원격 mutation도 실행하지 않았다.
- 실행 경로를 바꾸지 않아 별도 성능 비교를 추가하지 않았다. 기존 캐시와 요청 수 검사는 초기 실행에서 통과했다.
- 모든 입력과 모든 운영 장애를 검사했다는 뜻은 아니다. 보고한 범위는 읽은 구현과 실행한 기존 검사로 제한한다.

# 카테고리 테스트 입력 수정

두 카테고리 테스트의 입력을 실제 새 글 흐름에 맞췄다. 제품 코드와 UI는 수정하지 않았다.

앱의 `App.edit`는 선택한 분류를 임시 글의 `categoryId`로 전달한다. 새 글 API 응답에는 분류가 없다. 편집기는 임시 글의 분류를 초기값으로 사용한다. 기존 두 테스트는 임시 글 없이 서버 응답에만 분류를 넣었으므로 분류가 없는 상태에서 실패했다.

`tests/web/managed-block-editor.test.mjs`의 두 테스트에 분류를 포함한 임시 글을 전달했다. 새 글 응답의 잘못된 분류도 제거했다. 로컬 저장 검사는 해당 임시 글의 저장 키를 사용한다. 분류 표시, 버튼 위치, 취소, 확정, 태그, 독자 미리보기와 원격 저장 0회 검증을 유지했다.

## 검사 결과

- 수정 전 두 실패를 재현했다. 수정 후 같은 두 테스트가 통과했다.
- `npm run check`: 601개 중 600개 통과, 기능 실패 0개, 시간 초과 취소 1개. 종료 코드는 1이다. 전체 검사 통과로 판정하지 않는다.
- 취소한 검사는 `validates content when the inherited Git tree exceeds one MiB`다. 전체 실행에서 12.31초가 걸려 기존 10초 제한을 넘었다.
- 전체 검사와 자식 프로세스 종료를 확인한 뒤 해당 검사만 분리했다. 같은 코드와 같은 제한으로 3.14초에 통과했다. 병렬 실행의 자원 경합 가능성이 있으나 정확한 원인은 확정하지 않았다.
- 검사 시작과 종료의 입력 해시가 같다. `git diff --check`를 통과했다.

이번 수정은 테스트 입력만 바꿨다. 브라우저, 성능, 빌드는 다시 실행하지 않았다. 커밋과 배포도 하지 않았다. 원시 로그와 결과 JSON을 이 폴더에 보관한다.

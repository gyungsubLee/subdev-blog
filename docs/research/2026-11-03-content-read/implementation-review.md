# READ-PERF-01 독립 검토

검토자는 읽기 전용으로 변경 코드와 근거를 확인했다. 파일을 수정하거나 검사를 실행하지 않았다.

첫 검토는 `scripts/content.mjs`에서 첨부 목록이 없는 문서의 호환성 문제를 찾았다.
`JSON.stringify(undefined)` 뒤 `inventory.length`가 예외를 던졌다.
구현 담당자가 `review-red.log`에서 실패를 재현하고 첨부 수집 뒤 빈 목록을 정규화했다.
`targeted-fixed.log`는 해당 회귀 검사를 포함한 84개 검사의 통과 기록이다.

재검토에서 남은 수정 사항은 없었다.
검토자는 snapshot·원문·경로·첨부 문맥, gzip 협상과 응답 독립성을 확인했다.
head·계보 검사와 기존 메모리 상한을 우회하는 변경을 찾지 못했다.

메모리 합산은 보수적인 계산값이다. 실제 heap이나 RSS 측정값으로 쓰면 안 된다.
128 MiB 검사는 다른 보관 데이터가 경계 근처에 있다고 모사한다.
실제 bytes 추가가 기존 퇴출 함수를 호출하는지 검사한다.
최초·반복 본문 조회의 시간은 따로 보고해야 한다.
최종 전체 검사와 빌드는 구현 담당자가 실행한다.

# GitHub 인증 복구 결과

승인한 1–3번을 수정했다. Chrome과 새 네이티브 실행 파일에서 실제 로그인을 완료했다. 이번 작업에서 UI 파일과 세션 최대3600초 정책은 바꾸지 않았다.

## 변경한 동작

- GitHub GET은 통신 실패, 응답 본문 수신 실패, 기존5xx 조건에서 최대3회 시도한다.401·403과 쓰기는 재시도하지 않는다.
- OAuth 코드 교환은15초 제한을 적용한다. 한 번만 사용할 수 있는 코드이므로 재시도하지 않는다.
- 유효한 OAuth state와 PKCE challenge를 재사용한다. 오래된 콜백은 현재 쿠키를 삭제하지 않는다. 일치하는 콜백의 실패도 정상 세션은 보존한다.
- 웹의 세션 확인은 요청 하나를 공유한다. 전체 제한은30초, 일시 실패 재시도는1회다. 온라인·포커스·페이지 표시 이벤트는5초 간격으로 제한한다. 로그아웃 뒤 이전 응답은 버린다. 실제 unmount에서는 요청을 중단한다.
- HTML이나 JSON null로 온401·403도 HTTP 상태를 보존한다. 응답 형식 오류 때문에 접근 거부 요청을 재시도하지 않는다.
- 네이티브 앱의 활성 로그인 시작을 합친다. 서버는 앱이 POST로 수신을 확인할 때까지 완료 결과를 보존한다. 기존10분 만료와 인증 헤더 검사는 유지한다.
- Swift는 조회와 수신 확인의 통신·5xx 오류를 최대3회 시도한다. 헤더를 받은 뒤 끊긴 통신도 포함한다. 수신 확인 응답이 유실된 경우의410은 완료로 처리한다.

토큰 갱신, 상태별 UI 문구, 화면 구성 변경은 추가하지 않았다. 기존 권한·CSRF·불변 파일 캐시도 유지한다.

## 검사 결과

서버·웹·네이티브의 추가 회귀 검사에서 수정 전 실패를 확인했다. 최초 웹 검사 하나는 여러 pending 응답 중 마지막 것만 완료해서3초 제한에 걸렸다. 모든 응답을 완료하도록 검사 도구를 고친 뒤 정상적인 실패를 확인했다. 의미 있는 검사를 삭제하거나 약화하지 않았다.

최종 전체 `npm run check`는520개 중519개가 통과했다. 실패는 `tests/web/records-flow.test.mjs:92`의 `.back-link` 부재다. 해당 검사는 `BlogHarness → BlogView`를 사용하며 변경한 인증 훅과 API를 가져오지 않는다. 이번 작업에서는 기록 화면을 수정하지 않았다. [전체 검사 로그](check-final.log)에 결과가 있다.

전체 검사 뒤 JSON null 접근 거부의 조회를 보완했다. 이 최종 변경 이후 웹 복구 검사6개와 TypeScript 및 Vite 빌드가 통과했다. 전체 검사 결과를 최종1줄 변경까지 재실행한 결과로 해석하면 안 된다. [웹 검사](recovery-final.log), [빌드](build-final.log)를 확인한다.

Python 네이티브 검사2개가 통과했다. Swift 재시도 정책을 보완한 뒤 navigation 검사를 다시 실행해 통과했다. 검사에는 통신 실패200/202,401·403·410, 재시도 한도와 만료 조건이 포함된다. 독립 검토에서 발견한 제한 시간·본문 손실·null 응답 경로를 모두 반영했다. 최종 검토는 승인됐으며 검토자는 검사를 중복 실행하지 않았다.

## 실제 로그인

2026-11-04 KST에 실행했다. 새 Swift 바이너리의 실제 실행 경로를 `.tmp/native/auth-recovery/Second Brain.app/Contents/MacOS/SecondBrain`으로 확인했다. 앱에서 로그아웃한 뒤 로그인했다. `브라우저 로그인 중`에서 홈으로 돌아왔고 관리 메뉴·글쓰기·로그아웃을 확인했다. 쿠키 전달과 POST 수신 확인을 통과해야 홈으로 돌아오도록 연결돼 있다.

Chrome 전용 탭에서도 로그아웃 후 실제 OAuth 왕복을 실행했다. 홈 복귀 뒤 관리 메뉴와 글쓰기·로그아웃이 나타났다. macOS에 실제 통신 손실은 주입하지 않았다. 응답 유실과 재시도 경로는 자동 검사로 확인했다.

추가 계측 로그인에서는 GitHub가 접근 요청 횟수가 많다는 이유로 재인증을 요구했다. 기존 앱의 같은 권한으로 재인증한 뒤 콜백 성공 화면을 확인했다. 권한을 확대하지 않았다. 이후 로그인 반복은 중단했다. 이 화면을 과거 장애의 원인으로 단정하지 않는다.

로그인 검사 화면에서 공개 콘텐츠는 별도로 `GitHub request failed`를 표시했다. 인증은 `ready`였으며 관리 메뉴가 활성화됐다. 현재 checkout에는 이 작업 전부터 공개 콘텐츠를 바꾸는 동시 수정이 있었다. 이번 인증 수정이 공개 조회 문제까지 해결했다고 보고하지 않는다.

## 시간과 요청 횟수

동일한 계측 스크립트와 Mac에서 실제 GitHub 응답을 사용했다. 시각과 저장소 상태가 같지 않으므로 엄격한 성능 동등성 검사는 아니다.

- 수정 전:5,803 /2,255 /1,947ms. GitHub 요청12 /7 /7회.
- 수정 후19:54:43 KST:2,770 /1,701 /1,499ms. GitHub 요청12 /7 /7회.
- 모두 `ready`였다. 수정 후 세션을 전달받았을 때 남은 시간은3,589초였다.

정상 요청의 GitHub 호출 횟수는 증가하지 않았다. StrictMode와 수동 동시 갱신을 합친 검사에서는 요청 하나만 실행했다. 장애 재시도는 의도한 추가 요청이며 위 한도를 따른다. 시간 감소를 이번 수정의 성능 효과라고 단정하지 않는다. [수정 전](live-results.json), [수정 후](live-results-after.json)에 세부 측정값을 남겼다.

## 빌드와 제한

표준 `python3 app/native/build.py`는 웹 빌드와 Swift 컴파일 뒤 `iconutil: Invalid Iconset`에서 실패했다. 아이콘이나 빌더는 수정하지 않았다. 기존 앱의 동일한 아이콘·메타데이터·설정에 새 Swift 실행 파일을 조립하고 ad-hoc 서명 검사를 통과했다. 두 아이콘의 SHA256도 같았다.

검사한 앱을 `dist/native/Second Brain.app`에 반영하고 `codesign --verify --deep --strict`를 통과했다. `.tmp/native/auth-recovery/Second Brain.app`에서 같은 바이너리가 실행 중이다. 서버는 기존 로컬 포트5173을 사용한다. 데이터와 로그 경로는 바꾸지 않았다. 기존 `native/dist` 앱은 덮어쓰지 않았다.

커밋·푸시·운영 배포는 하지 않았다. 운영 로그인, 실제1시간 방치, macOS 통신 손실, 엄격한 성능 동등성은 미검사다. 수정 전 진단 파일은 과거 증거로 보존했다. 최종 소스와 빌드 해시는 `recovery-bindings.json`에 저장한다.

다음 행동은 로컬 diff를 검토하고, 별도로 관찰한 공개 조회 오류와 기록 화면 검사 실패를 해당 소유 작업에서 확인하는 것이다.

# 단일 요청 저장 독립 검토

독립 검토자가 구현을 승인했다. 검토자는 코드를 수정하거나 검사를 실행하지 않았다. 최초 검토와 범위를 좁힌 재검토에서 다음 경계를 확인했다.

- 단일 mutation은 `expectedHeadOid`로 충돌을 검사한다. 요청 확인 파일을 같은 커밋에 기록한다.
- 새 요청 ID는 `atomic-<UUID>`를 사용한다. 기존 UUID 요청과 저장 대기 기록은 기존 경로를 따른다.
- 응답을 잃으면 기기에 보관한 `sent` 기록과 별도 header로 읽기 복구를 먼저 요청한다. payload 해시는 바꾸지 않는다.
- 복구는 canonical의 확인 파일과 그 파일을 만든 커밋을 조회한다. 정확히 한 부모와 메시지·해시·기준 버전을 확인한다.
- 변경 없는 분류의 직렬화나 이미 확인한 원본 bytes를 바꾸지 않는다. atomic no-op은 요청 확인 파일만 추가한다.
- GraphQL의 일시 오류는 재시도할 수 있게 분류한다. 인증·실제 충돌·잘못된 내용은 별도로 처리한다.
- 첨부 참조가 base64로 크게 확장되면 사전에 크기를 계산한다. 큰 요청은 기존 SHA 경로를 사용한다. 파일당64KiB·합계1MiB 인라인 제한을 유지한다.
- 캐시 조회와 미리 채우기가 겹쳐도 같은 객체의 bytes를 두 번 합산하지 않는다. 기존32항목·8MiB·설정 범위를 유지한다.
- 원본 커밋 링크와 기존 공개 상태 UI를 유지한다.

집중 검사 로그는 `final-review-green.log`, `aggregate-green.log`, `atomic-green.log`와 `reconcile-green.log`에 있다. 서로 겹치는 검사 수를 합산하지 않는다. 실제 GitHub 실측과 로컬 HTTP·빌드는 루트가 별도로 소유한다.
